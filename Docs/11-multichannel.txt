# Multi-Channel Ingestion (Req 30)

Version: 1.0 · Owner: Platform

## 1. Overview

The framework accepts files from 6 channel categories and 10 subcategories.
Each channel is a **connector** — the validation, dedup, transfer, audit, and
reconciliation pipelines are identical across channels.

## 2. Channel taxonomy

Reference data lives in `fvi.channel_category` and `fvi.channel_subcategory`:

### 2.1 Categories (`fvi.channel_category`)

| code | description |
|---|---|
| `FILE_SYSTEM` | SFTP, network shares, enterprise filesystems |
| `CLOUD_STORAGE` | S3, ADLS, GCS, Azure Blob |
| `DOCUMENT_MANAGEMENT` | SharePoint, Box, Confluence |
| `DATA_PLATFORM` | Databricks Volumes, Snowflake stages |
| `WEB_UPLOAD` | Browser upload via UI portal |
| `API_PUSH` | REST or webhook-driven ingest |

### 2.2 Subcategories (`fvi.channel_subcategory`)

| code | category | MVP |
|---|---|---|
| `SFTP` | FILE_SYSTEM | ✓ |
| `INTERNAL_FS` | FILE_SYSTEM | — |
| `S3` | CLOUD_STORAGE | future |
| `ADLS` | CLOUD_STORAGE | future |
| `GCS` | CLOUD_STORAGE | future |
| `BLOB` | CLOUD_STORAGE | future |
| `SHAREPOINT` | DOCUMENT_MANAGEMENT | ✓ |
| `DBX_VOLUME` | DATA_PLATFORM | ✓ |
| `REACT_UI` | WEB_UPLOAD | ✓ |
| `REST_PUSH` | API_PUSH | ✓ |
